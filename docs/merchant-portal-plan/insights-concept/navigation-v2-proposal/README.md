# Proposed adaptive Insights navigation

Date: 1 November 2026. Status: PROPOSED_FOR_REVIEW. This is a separate revision proposal, prepared before approval of the revised screen. It has not replaced the existing Insights plan, changed the application or commissioned replacement concept images.

The proposed navigation is Overview, applicable business-specific insight tabs, and Reports in the same row. Overview summarizes the business. The business tabs explain orders, appointments, rentals, offerings, resources and other actual activities. Reports contains the searchable report catalogue, detailed reporting workspace, personal saved views and supported export history. They use the same registered measures and evidence.

Start with the [proposed screen and navigation plan](proposed-navigation-plan.md). The [merchant tab matrix](merchant-tab-matrix.md) and [structured matrix](merchant-tab-matrix.json) map all 128 baseline profiles and separately preserve the 21 previously approved source additions. Every new navigation mapping remains proposed. The [review scenarios](review-scenarios.md) define how to assess the design before replacing the current concept.

The [draft report catalogue](reports-catalogue-proposal.json) composes 26 proposed report identities using all 37 existing metric definitions. It gives Reports a concrete library while preserving one source of metric meaning across all tabs.

The two user-supplied references are saved unchanged as [business detail views](reference-detail-tabs.png) and [business overview views](reference-overview-tabs.png). They inform hierarchy and business terminology. Their example data, sidebar changes, labels, provider integrations and accommodation offering do not establish approved behavior or sources.

The earlier [screen design](../screen-design.md), [metric registry](../metric-registry.json), [source and implementation audit](../validation-plan.md), [merchant coverage](../coverage.json) and [twelve-image gallery](../images.md) remain the baseline. This proposal changes the proposed navigation and report organization. Existing definitions, permissions, source gates, workflow meanings and financial ownership still apply.

Static proposal checks are recorded in [verification.json](verification.json). They check source preservation, proposed tab mappings, metric references and local files. They do not test a working navigation, reporting calculations, authorization or accessibility.

# Collection composition engine

Status updated 19 October 2026. The F09 core and existing collection HTTP route are implemented, with separate contracts, release validation, request preparation, source-fact predicates and section selection. Read the [runtime](../../docs/COLLECTION_RUNTIME.md), [plan](../../docs/COLLECTION_IMPLEMENTATION_PLAN.md) and [verification](../../docs/COLLECTION_VERIFICATION.md). The approved editorial baseline remains disabled; enabled compatible releases are supported but were not published by this task. Exact complex anchor/comparison destinations await F10.

Compose useful homepage/category sections and related suggestions from explicit predicates and sufficient eligible supply.

## Contract

- Input: Reviewed collection definitions, intent/surface, category policies and ranked eligible references.
- Output: Collection keys, validated references, distinctness/underfill reasons and exact View all destination predicates.

## Versions

| Version | Planned work |
| --- | --- |
| V1 | Executable verified-fact predicates; distinct-entity minimum; suppress unsupported/empty/redundant sections. |
| V2 | Contextual section ordering based on judged usefulness and permitted session signals. |
| V3 | Constrained learned selection and appropriate complements, evaluated for relevance and merchant/category coverage. |

## Acceptance

View all applies identical eligibility; no new navigational categories; no fabricated inventory to fill rails; complements retain their own workflow and source identity.

Read the shared [architecture](../../docs/ARCHITECTURE.md), [ranking design](../../docs/RANKING_DESIGN.md), [contract](../../docs/INTEGRATION_CONTRACT.md) and [benchmark plan](../../docs/BENCHMARKS.md). Canonical taxonomy and platform source ownership apply to this module.

# Work frontend preview

Open Work from the existing Home preview, at `/merchant-live-preview/work` in development. The old Work preview URL redirects there. Work uses the same preview shell as Home. This is a sample-only frontend. No changes persist, and no live booking, inventory, payment, onboarding, Supabase or external provider is used.

The specialty list comes from `@nexg/booking-config/profiles`. The small `work-profile-views.json` map is derived from the reconciled Work design matrix; it exposes possible preview activities, not configured offerings. New profile definitions supplied to the Work configuration functions can suggest already registered model views without adding another portal. Publishing a new category and exposing it in the preview are separate future integration steps. Each chosen sample activity uses a shared workflow template and local `WorkSource` implementation. The test covers all 128 profile mappings, not all possible merchant configurations or full journeys.

`workActivitiesFromBooking` is a typed boundary for the booking engine's resolved selected-offering configuration: it only returns ready and active bindings, carries the offering and configuration revision, preserves linked execution, and reports unknown workflows. It does not create work, read onboarding, enable activities, authorize actions, or connect the screen to a live booking service. The preview currently selects its own samples and does not call this mapping. Real integration needs a source adapter and merchant-scoped configuration/records, with source-specific permissions, confirmation and error handling. Normal stock-confirmed orders must continue automatically; a merchant-review step is permitted only for a specific configured exception.

The present Work preview provides a shared queue/detail shell, filtering, sample milestones and local actions for the 18 planned workflow views. It does not yet implement every specialty-specific field, mixed-activity queue, action/evidence flow, external source state or operational scenario in the Work plan. Those remain frontend work to complete and verify before describing the portal as end-to-end ready.
